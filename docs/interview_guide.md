# 面试追问准备

## 为什么选择这个项目？

我希望做一个需要还原业务过程、而不只是汇总指标的运营分析项目。航班并非相互独立，同一架飞机会连续执行多个航段，前序延误可能影响后序航班。因此我选择用机尾号和时序还原轮转关系，把问题从“哪个航司延误最多”推进到“延误在哪里传播、哪里被吸收，以及缓冲应优先放在哪里”。

## 为什么使用 PostgreSQL？

SQL语法本身是核心。PostgreSQL对窗口函数、`FILTER`、`PERCENTILE_CONT`、时间间隔和执行计划支持完整，适合展示分析型SQL。项目中的核心逻辑也可以迁移到 MySQL 或 SQL Server，只需调整分位数和日期函数。

## 如何判断两个航班属于同一架飞机的连续航段？

先按机尾号和计划起飞时间排序，再用 `LAG` 取得前序航班。只有当前始发机场等于前序目的机场、前后航班均正常完成、计划间隔在0到12小时之间，才认定为有效轮转对。该规则是对公开数据的近似还原，不等同于航司正式排班。

## 为什么不能把取消航班的延误记为0？

取消航班没有完成到达，记为0会错误提高准点率。因此取消和备降进入完成率、取消率等指标，但不进入 OTP15 分母。

## 延误传播率能否证明因果？

不能。它表示在前序已经延误的条件下，后序继续延误的比例。后序航班还可能受到天气、空管、机组和机场拥堵影响。项目将其表述为诊断和优先级信号，而不是因果效应。

## 缓冲模拟有什么局限？

模拟只把计划起飞时间后移，再计算相对计划时间的延误变化。它没有纳入飞机利用率、机组工时、机场时刻、旅客衔接和成本，因此只能回答“在静态口径下可能覆盖多少延误”，不能声称真实降低了多少延误。

## 你怎么判断当前结果可以用于传播分析？

当前使用BTS 2024年1月完整月度数据，共识别461,224个有效轮转对，其中105,823个前序到达延误轮转进入传播率分母，超过程序设置的最低质量阈值。流水线对抽样文件仍保留自动质量警告；若有效轮转不足，就不会把传播率或缓冲情景写成业务结论。即使样本充分，58.8%的传播率也只代表条件相关性和当前月份，不是因果效应。
